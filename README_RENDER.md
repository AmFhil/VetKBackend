# VetKonect Backend - Docker & Render Deployment Guide

This Laravel backend application is pre-configured to be deployed as a Docker container on [Render](https://render.com).

## 🚀 One-Click / Blueprint Deployment on Render

1. Log in to your [Render Dashboard](https://dashboard.render.com/).
2. Click **New +** and select **Blueprint**.
3. Connect your repository (`https://github.com/AmFhil/VetKBackend.git`).
4. Render will automatically detect `render.yaml` and configure the Web Service with Docker.
5. Provide the required Environment Variables in the Render dashboard:
   - `APP_KEY` (Auto-generated by Render blueprint)
   - `APP_URL`: Your Render service URL (e.g., `https://vetkonect-backend.onrender.com`)
   - `FRONTEND_URL`: URL of your frontend (e.g., Next.js frontend URL)
   - `DB_CONNECTION`: `mysql` (or `pgsql`)
   - `DB_HOST`: Hostname of your MySQL / PostgreSQL database
   - `DB_PORT`: `3306` (or `5432`)
   - `DB_DATABASE`: Database name
   - `DB_USERNAME`: Database username
   - `DB_PASSWORD`: Database password
   - `RUN_MIGRATIONS`: Set to `true` to run database migrations automatically on start
   - Optional: Paystack / Mail credentials if using payment or mail features.

## 🛠 Manual Web Service Deployment on Render

If creating a **Web Service** manually instead of using Blueprint:
1. Choose **Build and deploy from a Git repository**.
2. Select your repository.
3. Set **Runtime** to **Docker**.
4. Set **Health Check Path** to `/up`.
5. Render automatically supplies the `$PORT` environment variable (10000). The container's entrypoint dynamically adjusts Nginx to listen on `$PORT`.

## 🔒 Security Note
- `.env` files are never committed to version control.
- All secrets and credentials should be configured securely via the Render Dashboard under **Environment Variables**.
